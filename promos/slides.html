It Shows You the Diff First

What would be created, what already exists, and which attributes differ — before a single thing is written.

  • Applying twice does nothing the second time
  • Down to individual attributes and field layout elements
  • Exits non-zero, so plan is a pull-request check
$ php craft archie/blueprint/plan blog.yamlFields + summary Will be created ~ articleBody 1 change: settings.initialRows settings.initialRows: 12 → 18 featuredImage Already matchesEntry types ~ article 1 change: fieldLayout.summary fieldLayout.summary: — → ContentPlan: 1 to create, 2 to update, 1 unchanged.

It Can Be Undone

Every apply records what each component looked like beforehand. Roll a run back and Archie deletes what it created and restores what it changed, newest first.

  • From the control panel or archie/history/rollback
  • Says plainly which deletions take content with them
Delete the section “team”
Delete the entry type “person”
Delete the field “personPhoto”
Restore summary.instructions←

3 of these delete something that holds content. Any entries, categories or assets inside them go too, and rolling back does not bring them back.
